One person builds this site, working with Claude, Anthropic's model. I decide
what goes in, bring the data only I can access (Search Console and GA4),
review every change, and merge every pull request. Claude writes most of the
code, tests, documentation, and article drafts, within rules the repository
checks for itself. What makes that output usable isn't the model. It's
that almost every rule a model could break is also a rule a test checks.

This page is part of the [Project section](/en/project), which documents how
the site is built. Everything here comes from
[my AI workflow
doc](https://github.com/Alf4kill/seotecnico.dev.br/blob/main/docs/ai-workflow.md)
in the repository, and every number below comes with the command that
reproduces it.

## Who does what

| Step | Me | Claude |
|---|---|---|
| Decide the next piece of work | Yes | Proposes it, in research notes and proposals |
| Search Console and GA4 data | I export it by hand from the project's properties | Reads the exports, never has the credentials |
| Research | I review | Writes dated notes, with an evidence label on each claim |
| Code, tests, documentation, drafts | I review and correct | Writes them, in a session with repository access |
| Pull request | I review and merge | Opens it, never merges |
| After merge | I request indexing and share it | — |

Work happens in two kinds of session. Editorial work, such as briefs and
draft reviews, runs in a session without repository access. Implementation
runs in one with access. Since the editorial session can't see the code, it
leaves `[CODE-n]` placeholders wherever any of the site's code would go, and
the implementation session fills them in by copying from the source file.
Before that rule, as PR #17 records, drafts arrived with invented code, such as
component files and prop shapes that don't exist in the repository.

## The contract: CLAUDE.md

Every session starts by reading `CLAUDE.md`, which declares itself the
project's single source of truth. Four things make it a contract for a model
rather than a wish list:

- **Numbered sections.** A commit, a review comment, or a skill cites "§10"
  instead of paraphrasing a rule.
- **Dated decisions.** Each rule carries its own date and who made it, as in
  "owner rule, 2026-10-23" or "rule since 2026-09-25". A later session can
  tell which rule is newer and why it exists.
- **The claims policy** (§10). Every claim is a mechanism, a condition, or a
  magnitude, and a magnitude requires a measurement with a declared method.
  This is the rule that keeps generated text from inventing numbers.
- **An out-of-scope list** (§13). It's as useful to a model as the scope
  itself.

## Rules that are tests

CI (`.github/workflows/ci.yml`) blocks the merge on any failure. Here's what
each check catches:

| Check | What it catches that a model could get wrong |
|---|---|
| Lint, type-check, 33 Vitest files | Broken code, schema builders, content parsing |
| Content loader (`src/lib/content.ts`) | A title over 60 characters, a description over 155, a short answer over 300, an unknown category |
| `content-code-paths.test.ts` | An article citing a repository path that does not exist |
| `hreflang.test.ts` | A translation pair declared on only one side |
| `design-rules.test.ts`, `design-tokens.test.ts` | A hardcoded color, a forbidden utility, a token out of sync |
| 8 Playwright specs | One H1, title and description, canonical, JSON-LD types, hreflang in both directions, contrast, accessibility |
| Lighthouse CI | Performance budgets |

A rule that matters but isn't a test yet tends to get broken. Take the
closing translation note on English articles. It was a convention,
not a check, and the two pairs published on October 23 went out without it.
That surfaced when the page-creation skill's pair script started checking
for the note.

## Scaling a claim down

Several commits exist only to make a sentence smaller and true. During the
October crawl audit, the apex domain refused connections from my network and
from an external checker. At first it looked like the site was down.
Commit `e376922` cut that reading down to what the evidence supported. A
TCP-only test reached the address from 17 of 18 nodes worldwide, and from a
node in São Paulo, Brazil. So the address was up. What failed was the route to
it from some networks.

Research notes follow the same habit, with a label such as **[documented]**,
**[inference]**, or **[observation]** on every claim.

## What stays with me

Five things I never delegate:

- **Merging.** No session merges its own pull request.
- **Secrets.** API keys live in Vercel environment variables. The project's
  Search Console and GA4 properties live in my personal Google account.
- **Search Console data, by hand.** No API pulls this data. The monitoring
  tools listed in `CLAUDE.md` (`gsc-monitor`, `nextjs-cwv-toolkit`,
  `ai-search-monitor`) have never run against this site. Every Search Console
  number in the repository comes from a manual export, dated in the file that
  records it.
- **The decision to publish.** Whether a topic deserves a page, and whether
  the page is ready.
- **Distribution.** I request indexing and post about the page by hand,
  after the merge.

Google looks at AI use the same way. Its spam policy targets scale without
value, not the tool, as the article on
[scaled content abuse](/en/blog/scaled-content-abuse) shows. This site's
experiments pre-register each hypothesis before the data comes in, a method
covered in [SEO testing with
pre-registration](/en/blog/seo-testing-pre-registration).
The [design colophon](/en/design) is the other page that explains a site
decision from the inside.

## Reproducing the numbers

```bash
git clone https://github.com/Alf4kill/seotecnico.dev.br && cd seotecnico.dev.br
git rev-list --count b141722
git log --merges --oneline b141722 | wc -l
git rev-list --no-merges --count b141722
git log --no-merges --format='%(trailers:key=Co-Authored-By,valueonly)' b141722 \
  | grep -i claude | sed 's/<.*//' | sort | uniq -c
git log --no-merges --format='%s' b141722 \
  | sed -E 's/^([a-z]+)(\([^)]*\))?:.*/\1/' | sort | uniq -c | sort -rn
```

Run on a newer commit, these commands return bigger numbers. The tables above
are a dated snapshot, not a live counter.
