## 1. What Google says

### 1.1 A 2xx is "consider for indexing", not "this page exists" **[documented]** — G1

For a 2xx response, Google passes the content on for processing. If the content
looks like an error (an empty page or an error message), Search Console
reports a soft 404. G1 also says a 2xx "doesn't guarantee indexing".

For 4xx (except 429), Google does not use the content: newly found 404 URLs are
not processed, already indexed ones are removed, and crawling of the URL slows
down gradually. 404 and 410 are treated the same way.

### 1.2 The Search Console definition **[documented]** — G3

The "Soft 404" row of the Page indexing report: the URL returns a
user-friendly "not found" message without a 404 status. Google recommends a
404 for pages that really do not exist, and more content on the page if it is
*not* an error. It points to URL Inspection's rendered screenshot to see what
Google saw.

**[observation]** G3's "Learn how to fix a soft 404" link goes to
`support.google.com/webmasters/answer/181708`, which now redirects to G1. G1
mentions soft 404 once, in the 2xx row, and has no section on fixing one.

### 1.3 Where the documentation moved **[documented]** — G5, G6

On 2025-12-18 Google moved "How HTTP status codes affect Google's crawlers",
"Optimize your crawl budget" and two other pages to the crawling
infrastructure site. The changelogs say functionality did not change, with
"minor wording changes".

### 1.4 Single-page apps **[documented]** — G2

- Use a meaningful status code: 404 for a page that was not found, 401 behind
  a login.
- "Avoid soft 404 errors in single-page apps": with client-side routing, a
  real status code can be "impossible or impractical". G2 gives two ways out:
  1. a JavaScript redirect to a URL **for which the server responds with a
     404** (example: `/not-found`);
  2. `<meta name="robots" content="noindex">` added with JavaScript on the
     error view.
- Pages with a 200 go to the rendering queue; on a non-200 response "rendering
  might be skipped" (note added 2025-12-18, G5).

**[inference]** Way 1 works only if the target URL itself answers 404. A
redirect to an error page that answers 200 is still a soft 404, now with a hop
before it. That is the S3 case below.

### 1.5 Crawl cost **[documented]** — G4

- Soft 404 pages "will continue to be crawled", wasting crawl budget; 404 or
  410 is a strong signal not to crawl the URL again.
- G4 counts each hostname as a separate site with its own crawl budget.
- G4 is written for large sites (1M+ pages, or 10k+ changing daily, or many
  URLs in "Discovered – currently not indexed") and says smaller sites do not
  need it.

**[inference]** The crawl-budget argument applies to a small site only where
the URL space is unbounded (a template that answers 200 for any slug). The
usual harm for a small site is a not-found view that is indexed, or a real page
that is classified as a soft 404 because it looks empty.

## 2. Next.js App Router

### 2.1 Two conventions **[documented]** — N2

`not-found.js` renders when `notFound()` is thrown in a segment.
`global-not-found.js` handles URLs that match no route, at the routing level.

### 2.2 Streaming fixes the status at 200 **[documented]** — N1, N3

- `notFound()` returns a 404 when it runs before the response starts
  (including at prerender).
- After streaming has started (a `loading.js` or `<Suspense>` fallback was
  sent), the status stays 200; Next.js injects `noindex` in the streamed HTML.
  N3 says some crawlers "may label these responses as 'soft 404s'".
- With Cache Components, the shell is sent first, so a request-time existence
  check in the page keeps 200.
- N3's remedy: check before streaming (for example in Proxy) and rewrite to a
  not-found route or return a 404 response.

### 2.3 Streaming metadata makes the status depend on the User-Agent **[documented + observation]** — N4, G9

N4: since 15.2, `generateMetadata` can stream. For "HTML-limited bots"
(detected by User-Agent; the default list is `HTML_LIMITED_BOT_UA_RE` in
`next/dist/shared/lib/router/utils/html-bots.js`), Next.js waits for
metadata before starting the response. Googlebot is not on that list (N4
names it as a bot that runs JavaScript); `Google-[\w-]+` and `Bingbot` are.
G9: `Google-InspectionTool` is the agent of URL Inspection and the Rich
Results Test.

**[observation]** Minimal app on `next@16.2.12` (this repo's), `next build
--webpack && next start`, 2026-11-09T02:20Z. One missing slug per route, five
User-Agents (Chrome, Googlebot smartphone, Google-InspectionTool mobile,
Bingbot, curl), `Accept: text/html`:

| Route variant | Chrome | Googlebot | InspectionTool | Bingbot | curl |
|---|---|---|---|---|---|
| `notFound()` in the page, no `loading.tsx` | 404 | 404 | 404 | 404 | 404 |
| same + `loading.tsx` in the segment | 200 | 200 | 200 | 200 | 200 |
| `notFound()` in both `generateMetadata` and the page | 404 | 404 | 404 | 404 | 404 |
| `notFound()` **only** in `generateMetadata`, page renders at once | **200** | **200** | 404 | 404 | **200** |

Every response carried `<meta name="robots" content="noindex">`. In the last
row the 200 responses also carried the page body and the not-found UI.

**[inference]** In the last case, URL Inspection's live test (404) does not
show what Googlebot gets (200 + `noindex`). The tool can mislead exactly where
the bug is. Real-world reports: `vercel/next.js#77235` (2025-03, "since
v15.2.0", closed as expected behavior).

The app's source is kept outside the repo for now; versioning it as a lab
fixture is an owner decision (brief §9).

## (a) Claims the article can make

| Claim | Level (§10) | Source IDs |
|---|---|---|
| A 200 response means "consider for indexing", not "this page exists"; content that looks like an error is reported as soft 404 | 1 | G1, G3 |

## (d) Proposed angle and primaryQuery

**Angle (fits §13: how a crawler reads a status code).** A soft 404 is rarely a
decision: it is a side effect of the architecture, and it can be tested from
outside with one invented URL. Three ways sites end up answering 200 for a page
that does not exist (template with no existence rule; SPA on a static host;
redirect to an error page that answers 200), the one-request test, the fix per
case, and the Next.js case where the framework itself keeps 200 (streaming).

**First-hand element:** the probe of this site (§2.4), the re-measured
anonymous cases (§3.1), the Next.js lab table (§2.3), and the repository's own
not-found setup. The lab table is the strongest: it answers a question
developers keep filing (Q3) and shows where Google's own test tool sees a
different status (Q5).

**Layer (§5.2):** 1, generic hub; closing "No Next.js" section with
`global-not-found.tsx`, `dynamicParams = false` and the streaming caveat.

**primaryQuery:** `soft 404` (PT and EN; the pt-BR help page of G3 names the
row "Erro soft 404", so Brazilian users meet the English term). No published page has an equivalent query; `javascript seo`
covers rendering, not status codes. Demand: **não verificado** (c3).
